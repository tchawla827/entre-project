# Simulator design and data contract

The typed models in `src/digital_twin/schemas.py` validate UTC route clocks, nonnegative finite stage/event durations, finite temperatures, and connected timestamp intervals. `routes.py` builds a route from the air YAML or the sea overlay. An `event` applies within its named stage; an out-of-stage event fails. Zero-duration stages produce no samples and zero exposure. A scenario mutation creates a fresh route; it cannot mutate another run's config. The resolved route/scenario, seed, generator metadata, and parameters contribute to the run ID.

For constant target `u` and interval `Δt`, air state updates as `T_next = u + (T_current − u) exp(−Δt/τ_air)`. `simulation.py` also analytically updates a separate first-order illustrative product-lag state driven by this air trajectory. Refrigeration-off and door-open target the assumed ambient temperature; door-open uses the faster assumed air response. At stage boundaries both states carry forward continuously. The configured sampling grid is split at event starts/ends. Proxy mode offsets synthetic setpoint targets with detrended, continuously timed residuals from nonfish measurements. This does not turn source readings into route air measurements.

`exposure.py` calculates positive temperature-area above each reference and time above it by linear interpolation within each *actual elapsed-time interval*. Interval length, rather than sample count, determines weight; a crossing is integrated geometrically. Input gaps, overlaps, duplicate intervals, nonfinite values and nonpositive intervals are rejected. `simulation.py` returns route, stage and event summaries; `experiments.py` compares route-level and stage-level scenarios and performs exact Shapley attribution for the three named *air* interventions. It is a contribution of modeled interventions, not a biological causal estimate. Event-window comparisons use stage-local time and state carryover is flagged.

`result_tables` exports UTC ISO-8601 interval rows to Parquet. Detailed metrics JSON carries `schema_version: 1`, run metadata, nested air and `estimated_product` exposure summaries, input assumptions, source provenance, and Phase 2 capability statuses. Scenario and stage CSVs are human-readable flat projections. See the full [handoff](final_handoff.md) for paths and commands. A future calibrated adapter can consume measured species/product/quality/temperature inputs, but `phase2_adapter.py` currently refuses unsupported predictions via `UnsupportedCalibrationError`.
