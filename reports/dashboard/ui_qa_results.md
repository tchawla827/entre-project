# Focused UI QA

The local Streamlit server was restarted with the new theme and remained reachable at `http://localhost:8501`. `python tests/dashboard/browser_qa.py` used real Chromium clicks to run the air road-failure case, open the scenario comparison, change to sea/citrus-proxy/assumed-product-lag/4 °C, run again, and download the current ZIP. The ZIP's complete JSON matched all four selected filters. Five desktop/mobile screenshots were saved in [`figures/dashboard/redesign/`](../../figures/dashboard/redesign/). The browser reported **zero page errors**; mobile document width was **390 px** at a 390 px viewport.

Visual inspection found the first mobile screenshot had an open sidebar obscuring the content because the app forced `initial_sidebar_state="expanded"`. Changing this to `"auto"` made fresh mobile loads start with the sidebar closed. The initial desktop screenshot was also taken before Plotly finished rendering; the browser test now waits for a rendered chart. The final road-failure and scenario-comparison charts were visually inspected after those fixes.

`python -m pytest tests/dashboard tests/integration tests/digital_twin tests/models tests/data_pipeline -q` passed **38/38, 0 failed, 0 skipped**. Eight warnings are dependency deprecations in the existing joblib/NumPy and cold-room timestamp paths. The Phase 4 CLI validator returned `passed: true` with 48 runs, 192 comparison rows, 1,344 stage rows, stage conservation and biological refusal checks all true. The browser test does not replace a full keyboard/screen-reader accessibility audit.
